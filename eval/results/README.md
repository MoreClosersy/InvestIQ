## 受控对照结果

同一份冻结输入，只改 agent 门控逻辑：

| 结果分类 | 修复前 (`..._074011`) | 修复后 (`..._080739`) |
| --- | --- | --- |
| 成功（有数据且有分析） | 20 | 20 |
| **正确拒答（无数据且未编造）** | **1** | **4** |
| **幻觉（无数据却生成分析）** | **3** | **0** |

修复前被误判为「完全成功」的 3 条，是 `ZZZZZZ` / `NOTAREAL` / `12345`：它们
没有任何财务数据，却各自产出了 strengths/risks——内容完全由通用新闻拼出。

## 数字接地检查（当前基线的额外结论）

`..._080739` 的接地检查结果：700 个报告数字中，**286 个有财务出处、
414 个只来自新闻、0 个无出处**。

所以「无出处 = 0」并不等于没问题：**接近六成的数字是从新闻里拿的**，
没有经过 yfinance 那道结构化管线。这就是 README 里「What I'd do next」
中 `Cross-source fact verification` 那一条被量化后的样子——该做的交叉校验
还没做，但**暴露面已经量出来了**。

## 一个值得注意的细节

`20260911_052118`（实时输入）那次是 **4** 条幻觉，受控对照里是 **3** 条
（`INVALID` 那天恰好在新闻侧也没搜到东西，于是旧逻辑的
`not has_news and not has_financial` 分支碰巧把它挡住了）。

**同一个 bug，因为输入不同，数量就不一样。** 这正是必须先冻结输入的原因——
不然你连「bug 有几个」都复现不了。

## 指标版本差异（如实记录）

`..._074011` 产出在接地检查和几处「空值不再伪装成满分」修正**之前**：

- 它的记录里没有 `grounding` 段（但报告正文已归档，用当前代码重算可以得到）；
- 它没有归档 `change_pct` / `period_high` / `period_low`，所以对它跑接地检查会产生
  **假阳性**——报告里的「日涨跌幅」会被判成无出处。**这是证据缺失，不是模型编造。**

这些差异都不影响上面受控对照表引用的任何数字（那张表只看结果分类计数）。
当前基线请用 `..._080739`。

## 一个反直觉的教训

接地检查第一版报出 42 个「无出处」数字，逐个分诊后发现**绝大多数错在检查器自己**：
`52-Week` 里的 `52` 被当成数字断言、`$109.42 billion` 对不上 `$109.42B`、
容差用固定百分比导致该松的没松该紧的没紧。

补齐归档字段、修完分词与容差之后，**这个数字归零**。

**「无出处」意味着「我没能验证」，不等于「它是编的」。** 一个会把自己证据缺失
报成模型编造的检查器，比没有检查器更危险——因为它会让人去修不存在的问题。
